A RAG demo, pointed at Strudel

Trigger
Not recorded. These are the first commits.
Commits
  • ec34e50Initial commit
  • 0cd8726simple rag

The repository opened with a licence and a two-line README. About eight hours later, a commit called "simple rag" landed the skeleton that still runs today: a LangChain agent on gpt-4o-mini with a single tool, retrieve_context, searching a Pinecone index built by crawling strudel.cc with Tavily and splitting pages into 4,000-character chunks. The interface was a Streamlit chat.

The tool already returned its documents as a separate artifact next to the text the model reads. That is still how the page cites its sources.

Inferred

The ingestion script's first docstring read "Lesson 6 / ingestion - Crawl python.langchain.com and index it into Pinecone". The pipeline most likely began as a course exercise on LangChain's docs and was retargeted at Strudel.

26 Aug · 17:42 – 18:34

Hybrid search and the function reference

Trigger
Not recorded.
Commits
  • c576da4Add new dependencies and update package configurations
  • 03142f6Refactor code structure for improved readability and maintainability

Two commits in under an hour made retrieval good at Strudel in particular, and neither title says so. The first added BM25 alongside Pinecone through an EnsembleRetriever, so an exact function name like lpf surfaces even when embeddings rank it low. It also gave chunks content-addressed ids and a local dump, data/chunks.json, which the lexical side reads.

The second taught ingestion to read Strudel's source code. The function reference is not a crawlable page; the REPL renders it from JSDoc comments in the Strudel repository. Ingestion now fetches those files from Codeberg and turns each documented function into one document, never split.

The same commit added all_docs_prototype.json: 378 function entries, each with a name, tags, synonyms, parameters and a description. Its role as a prototype of that extraction is inferred from its name and shape.

Seventeen minutes after phase 02, a Gradio chat replaced Streamlit on a side branch. That branch was never merged, and no commit says why.

The next afternoon, a commit titled as a stylesheet did far more: it deleted the Streamlit app and replaced it with a FastAPI server and a hand-built page with no framework and no build step. Part two · hum to pattern
04

12 Sep · no commit

Could it listen?

Trigger
A question: could an iOS app record someone singing and have the assistant rebuild it in Strudel?
Decided
The input is a hummed or sung melody, not beatboxing or spoken words. The app is a Capacitor wrapper around the existing page, not a native rewrite.

One rule was set before any code and survived everything after it: the model never hears the audio. Signal processing measures pitch and timing, and the agent receives facts plus a skeleton to make musical. Phase 08 later tested that rule head-on.

05

12 Sep

Hearing notes in a clean hum

Trigger
The core of the feature, built first because nothing else matters if a hum doesn't transcribe.
Commits
  • 4aa931dfeat(melody): transcribe hummed audio into a Strudel skeleton

app/backend/melody.py tracks pitch with pYIN, rounds each frame to a semitone, groups runs into notes, snaps them to a sixteenth-note grid, estimates the key and writes mini-notation. The syntax was checked against the project's own corpus first: ~ for a rest, @n to hold, lowercase note names such as c#4.

No recording of a person has ground truth, so the tests synthesize hums from known melodies.

06

12 Sep

Recording in the page, on every screen

Trigger
Wiring transcription to a microphone, then a request to design for phone, tablet and desktop.
Commits
  • d7b6e6bfeat(api): add /api/hum, transcription plus pattern generation
  • b959db9feat(web): record a melody and get a pattern back

POST /api/hum takes a recording, transcribes it, and passes a prompt to the same agent that answers chat. It returns two patterns: the literal transcription, which needs no model and still comes back when the model call fails, and the agent's elaborated version.

The page records with the browser's recorder but uploads 16 kHz mono WAV, decoded and resampled in the page, because the server's audio library reads neither the WebM Chrome produces nor the AAC Safari produces. The preview browser blocks microphones, so end-to-end tests used a hum synthesized inside the page. That surfaced problems no unit test could.

Course corrections

TriedWhat happenedReplaced with
piano as the default soundPlayback failed: the page loads only the dirt-samples drums and the built-in synthstriangle, and the prompt lists what is loaded
Telling the agent to add .slow(2)It dropped it often enough that melodies played at double speedHand it the finished expression, and restore .slow(n) on the server when it is still missing
A grey record dot that turns red on hoverPhones have no hover, so the only control on a phone looked disabledRed at rest, dimmed

Two more prompt rules went in, against variable assignments and against soundfonts the page never loads. Each caught the failure it named, and the model found variations. Phase 09 is the story of why rules stopped being the answer.

07

12 Sep

A native shell for iOS

Trigger
The Capacitor decision from phase 04.
Commits
  • 2d88161feat(mobile): wrap the web app as an iOS app with Capacitor

mobile/ wraps the same page in Capacitor. The Python backend cannot run on a phone, so the app serves the page from its bundle and calls the server over the network. That makes the app a different origin from the API, which is why the page gained a configurable API address and the server gained a CORS allow-list.

A sync script copies the page into the app and injects a generated config.js. A second script patches what Capacitor's template leaves out: the microphone permission text, without which iOS kills the app on the first recording; an audio session that keeps Strudel audible in silent mode and on the loudspeaker after recording; and permission to reach a Mac over plain http during development.

Not built

The patcher was tested against the real template extracted from @capacitor/cli and runs safely twice. The app itself was never built: this machine has no Xcode and no CocoaPods.

Choosing models by measurement

Trigger
A question: which OpenAI model would help most with sound and music?
Commits
  • 87566a2perf(agent): switch to gpt-5.4-mini

The question split in two, and each half was tested on this app's own task rather than answered from reputation. First: could an audio model replace the signal processing? Three were sent the same clean synthetic hum that melody.py transcribes exactly.

Audio model, two attempts eachCorrect note sequences
gpt-audio-1.5, gpt-audio, gpt-audio-mini0 of 6

Every tempo was wrong too, and no model agreed with itself between attempts. Phase 04's rule stands. Second: which chat model writes the Strudel? Five runs each through the full pipeline, scoring whether the melody survives verbatim, .slow(n) is kept, no variable assignment appears, and no unloaded soundfont is used.

09

12 Sep

An agent that checks its own work

Trigger
A request to design the assistant as a ReAct loop, with a sandbox where it helps.
Commits
  • 9a480c7feat(sandbox): evaluate Strudel patterns in a locked-down Node process
  • 46ed8bbfeat(agent): turn the agent into a ReAct loop over the sandbox

With one tool, the agent's loop had nothing to react to, and the prompt had become a list of failures to avoid. The fix was a second tool that returns ground truth. validate_pattern runs a candidate pattern in Node with the real Strudel engine and reports what it does, or exactly how it fails. The agent now searches, writes, validates and repeats until the verdict is clean. The sandbox queries patterns and never plays them, so it needs no audio device.

Getting Strudel to run headless

  • Importing @strudel/core threw before any of its code ran: its published dependency @kabelsalat/web no longer exports a class it needs, in any of the five versions tried. A small stub supplies it.
  • $: compiles to a method that lives in the audio engine's module, so the sandbox reimplements it: collect each pattern, stack them, query the stack.
  • Strudel prints a banner on import, which corrupted the JSON report. Stray output now goes to stderr.
Measured

Without Node's permission flags, a pattern wrote a file to /tmp. With them, file writes, network access and subprocesses all failed while ordinary patterns still evaluated. The flags are a security control, not tidiness.

First self-correction

Asked for a bassline on gm_acoustic_bass, a soundfont the page never loads, the agent searched twice, validated, got a warning, switched to triangle and validated again, in 7.5 seconds. Without the tool it would have shipped a silent pattern. With the sandbox in the loop, a typed answer took about 5.7 seconds and a hummed melody about 9.6.

Caveat

With the sandbox added, gpt-4o-mini went from 1 to 5 clean runs out of 5. But the validator reported no errors in any of those runs, and the prompt changed at the same time, so that gain is not credited to the sandbox.

12 Sep · 15:27 – 15:28

Surviving a real voice

Trigger
A request to carry on alone. A human voice had still never been tested.
Commits
  • d881504fix(melody): survive a real hum, not just a clean tone
  • e026fd3test(melody): add the realistic-hum suite that drove the rework
  • e8c1274docs: record the new segmentation, the new tempo method and the numbers

Without a voice to test, the test signal was made to behave like one: pitch that slides between notes, breath noise ten times louder, uneven timing and loudness, room rumble, and a singer drifting flat. The pipeline that passed on clean hums failed on the first run.

Course corrections

TriedWhat happenedReplaced with
Cutting notes at spectral onsetsOn a noisy take, breath noise hid the attacks: it caught every pitch change and missed every repeated noteCut at dips in loudness, because humming a note twice means closing and reopening
Tempo from beat trackingWithin 10% in 9 of 21 noisy takes. It keys on percussive attacks a voice doesn't makeThe median gap between note starts, measurable once note boundaries were accurate
A 70 bpm tempo floorA melody hummed at 70 was read as 138: noise put it just under the floor, and it was doubledA 60 bpm floor, in a 60–180 window

Result

MeasureClean, phase 05Clean, nowRealistic, now
Key7 of 77 of 721 of 21
Note sequence6 of 77 of 720 of 21
Tempo6 of 7 within 2%7 of 7 within 5%21 of 21 within 10%

On clean hums, one tempo that used to be exact now lands 2% out, and the one that was wrong by a third now lands within 4%. The clean tolerance widened to 5% to say so openly. The test suite grew from 14 tests to 36, and it pins the repeated-note failure so it cannot return quietly.
