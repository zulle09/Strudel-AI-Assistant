Technical architecture

StrudelAssistant Signal Chain

A documentation assistant for Strudel that answers typed questions and hummed melodies with patterns that play in the page. This is the path a request takes from a text box or a microphone to sound, and every boundary it crosses on the way.

System map

One server, two ways in, one agent

At request time there are three things running: a single FastAPI process, a short-lived Node process for each pattern the agent checks, and a web page. Ingestion is a separate program run by hand. It never shares a process with serving, and meets it only through the two indexes it writes.

Request paths

The hum path is the chat path with transcription in front

Both endpoints end at the same agent and render markdown the same way. Everything the hum path adds is deterministic: capture and encoding in the page, transcription and prompt construction on the server, and a repair step behind the model.

Startup
core.py builds the BM25 index and opens Pinecone at import, so the server imports it lazily behind a lock and warms it on a background thread. The page loads instantly, and a missing key becomes a readable message in the chat instead of a crash at boot.
Threads
Both endpoints are plain def, so FastAPI runs them on worker threads while retrieval, the model and transcription block.
Hum statuses
400 empty upload · 413 over 8 MiB · 422 unusable recording, with a sentence for the singer · 200 with a warning when only the model leg failed
Rendering
markdown-it with raw HTML disabled and tables enabled. Answers are derived from crawled third-party text, so model output never becomes markup.
Debugging
STRUDEL_DEBUG=1 sends tracebacks to the page as well as the terminal.
Agent loop

A ReAct loop whose observations are ground truth

run_llm() builds a LangChain agent on gpt-5.4-mini with two tools, and a system prompt that tells it to use them in a loop rather than once each. Retrieval is how it learns. The sandbox is how it checks what it wrote, and because it runs the real Strudel engine, its verdict settles questions that prompt rules kept losing.

A recorded trace

Asked for a bassline on gm_acoustic_bass, a soundfont this app never loads.

  1. ACTretrieve_context("Strudel gm_acoustic_bass sound lowpass filter lpf wobble…")

  7. OBSVALID. 32 events. Sounds used: triangle. Distinct notes: 4.

Model
gpt-5.4-mini through init_chat_model, chosen by benchmark. See Model choices.
Lifetime
A fresh agent is built on every request. Cheap at this scale, wasteful at any other.
Degraded mode
If Node or sandbox/node_modules is missing, the tool says so and the agent answers from documentation alone, flagging the pattern as unverified.
Latency
About 5.7 s for a typed answer and 9.6 s for a hummed melody with the sandbox in the loop, each measured once.
Retrieval

Hybrid search, and a return value the model only half sees

retrieve_context queries a lexical and a semantic index and fuses the two rankings. BM25 catches exact function names that embeddings rank low, and the vector side catches paraphrases. The less obvious part is what the tool hands back.

Lexical
BM25 over data/chunks.json, rebuilt in memory at import, k = 10
Semantic
Pinecone strudel-doc-index, text-embedding-3-small, 1536 dimensions, k = 10
Fusion
EnsembleRetriever, weighted reciprocal rank fusion, 0.5 / 0.5
Fallback
Vector-only when chunks.json is missing
Corpus
Tutorial prose crawled from strudel.cc, plus one reference entry per Strudel function parsed from its JSDoc. The prompt tells the model to trust reference entries over its own memory of the language.
Transcription

Signal processing decides the notes; the model never hears audio

Three OpenAI audio models were given a clean synthetic hum and got the note sequence wrong in all six attempts. So backend/melody.py measures pitch and timing with librosa, and the agent receives facts plus a mini-notation skeleton it is told to keep verbatim.

The chain

  1. DecodeWAV to mono float32 at 22,050 Hz. libsndfile cannot read AAC, which is why the page uploads WAV.
  2. TrimLeading and trailing silence more than 30 dB below peak.
  3. PitchpYIN between C2 and C6, 2048-sample frames, 256-sample hop, 11.6 ms per frame.
  4. BoundariesValleys in RMS loudness with prominence 0.15, at least 90 ms apart.
  5. NotesSemitone runs cut at pitch changes and boundaries. Gaps under 60 ms merge, fragments under 80 ms drop.
  6. TempoMedian gap between note starts, folded into 60–180 bpm, snapped to a multiple of 5 within 1.5%.
  7. Grid16 steps per cycle and one 4/4 bar per cycle, so cpm = bpm / 4.
  8. KeyDuration-weighted pitch classes against Krumhansl–Schmuckler profiles, all 24 keys.
  9. OutputMini-notation, .slow(cycles) for melodies longer than a bar, and a JSON summary.

How well it holds up

MeasureClean humsRealistic hums
Key7 of 721 of 21

Tempo7 of 7 within 5%21 of 21 within 10%

No recording of a person has ground truth, so reference hums are synthesized from seven known melodies between 70 and 150 bpm. The realistic generator adds portamento, loud breath noise, timing jitter, uneven loudness, room rumble and a singer drifting flat, with three random seeds each. It is the suite that forced loudness-based boundaries and interval-based tempo; before them, the same takes lost every repeated note and got tempo right 9 times in 21.

Sandbox

The model's code runs in a process that can touch nothing

sandbox/validate.mjs reads a pattern on stdin, evaluates it with the real Strudel packages, queries four cycles, and writes a JSON verdict on stdout. It never plays audio. Querying is Strudel's own way of asking which events fall between two points in time, so it is pure computation.

Pattern handed to the sandboxVerdict
note("c4").sound("triangle").frobnicate(3)Invalid: frobnicate is not a function
slower = slow(2)Invalid: slower is not defined
note("c4@@ [[[")Invalid: mini-notation parse error, with position
note("c2 g2").sound("gm_acoustic_bass")Valid, with a warning that the soundfont is not loaded
silenceValid, with a warning that it produces no events
A pattern that never returnsStopped at 20 s
Dependency stub
@strudel/core 1.2.6 imports SalatRepl from a @kabelsalat/web that no longer exports it, in every published version tested. sandbox/stubs supplies the export and throws if audio is ever requested.
$: handling
The real .p() lives in the module that builds the audio engine, so the sandbox reimplements it: collect each pattern, stack them, query the stack.
Sound names
Resolved at playback, not at query time, so no query can fail on them. The sandbox lists the sounds a pattern asks for and flags gm_ soundfonts by name.
Frontend

One page, no build step, the real Strudel engine

app/web is hand-written HTML, CSS and JavaScript served straight off disk: 103, 841 and 1,063 lines. @strudel/web 1.3.0 loads from unpkg, pulls the dirt-samples drum banks from GitHub on first play, and synthesizes in the page.

Transport
One engine, one active source at a time. The lane in the top rail is driven by scheduler.now(), the engine's own cycle position, not a timer at a guessed tempo.
Pattern modules
decoratePatches() turns every fenced block in an answer into a panel with Play, Edit and Copy.
Editor
A transparent textarea over a highlighted copy, so caret, selection and undo stay native. ⌘/Ctrl+Enter swaps the pattern without stopping playback. Contents and width persist in localStorage.
Errors
Strudel reports failures as strudel.log events rather than rejected promises. The page listens and shows them in the rail.
History
The client keeps answer_md, not HTML, so the next turn sends the model its own words.
API base
window.STRUDEL_API_BASE, empty in a browser and set by config.js in the iOS bundle.

Capturing a hum

  1. getUserMediavoice processing off
  2. MediaRecorderWebM or MP4, ≤ 30 s
  3. decodeAudioDataany format
  4. OfflineAudioContext1 channel, 16 kHz
  5. encodeWav16-bit PCM
  6. POST /api/hummultipart

Echo cancellation, noise suppression and gain control are tuned for speech and flatten the steady tone pitch tracking needs, so they are switched off. Decoding in the page means the server sees one format whatever the browser recorded, and the upload shrinks by an order of magnitude.

iOS shell

The same page in a native wrapper, calling your Mac

mobile/ is a Capacitor 7 project with no interface of its own. The Python backend cannot run on a phone, so the app serves the page from its bundle and calls the server over the network, which makes it a different origin from the API.

Microphone key
NSMicrophoneUsageDescription. Without it iOS terminates the app the moment getUserMedia is called.
Audio session
.playAndRecord with .defaultToSpeaker. Otherwise Strudel is silent in silent mode, and moves to the earpiece after the first recording.
Local network
NSAllowsLocalNetworking lets plain http reach the Mac during development. Remove it before shipping.
Origin
Requests arrive from capacitor://localhost, which the server's CORS allow-list admits. STRUDEL_ALLOWED_ORIGINS adds more.
Verified
The patcher was run against the real template extracted from @capacitor/cli, is idempotent, and prints a manual snippet if a future template stops matching. Nothing has run on a device.
Ingestion

An offline program that builds both indexes

Strudel's function reference is not a crawlable page. The REPL renders it from data generated out of JSDoc comments in the Strudel source, so ingestion combines a crawl of the tutorials with a parse of the source itself. It is long-running and paid, and meant to run once.

Tutorial prose

  1. TavilyCrawlstrudel.cc, depth 3
  2. select_pathsworkshop, learn, recipes
  3. Documentone per page
  4. RecursiveCharacterTextSplitter4,000 chars, 200 overlap

Function reference

  1. Codeberg tree APIpackages/**/*.mjs
  2. raw files3 at a time, retry on 429
  3. /** … */one doc per @name, never split

Both, then

  1. sha256(source + text)content-addressed id
  2. data/chunks.jsonoverwritten
  3. Pineconeupserted, batches of 500

Content-addressed ids mean unchanged chunks upsert onto themselves. The flip side is drift: a changed chunk gets a new id, and its old vector stays in Pinecone after chunks.json has forgotten it.

Model choices

Measured on this app's own task

Five runs each through the full pipeline on the melody prompt. A run counts as clean when the melody survives verbatim, .slow(n) is kept, no variable assignment appears, and no unloaded soundfont is used.

ModelClean runsMean time
gpt-5.4-miniin use5 of 54.5 s
gpt-6-astra5 of 510.1 s
gpt-5.55 of 512.6 s
gpt-5.6-sol5 of 524.3 s
gpt-4o-mini, previously1 of 55.2 s

The smallest current model was both the most reliable and the fastest, so the larger ones buy nothing here. gpt-6-astra and gpt-5.6-sol reject function tools on the Chat Completions path and need the Responses API, which returns content blocks the answer extraction does not yet handle. Pricing was not compared. With the sandbox added, even gpt-4o-mini reached 5 of 5, but the validator reported no errors in those runs and the prompt changed at the same time, so that gain is not credited to the sandbox. Audio models were ruled out separately: gpt-audio-1.5, gpt-audio and gpt-audio-mini returned no correct note sequence in six attempts.

Invariants

What breaks quietly if you change it

Security

The sandbox permission flags

SANDBOX_FLAGS is the only thing between model-written code and your disk, network and processes. Without them a pattern wrote to /tmp.

Security

Answer HTML stays escaped

markdown-it runs with raw HTML off. Answers derive from crawled third-party text.

Data

One embedding model, two files

ingestion.py and core.py must both use text-embedding-3-small. Changing it means re-indexing and recreating the index at the new dimension.

Data

BM25 and Pinecone drift apart

The chunk dump is overwritten and Pinecone is upserted. If retrieval surfaces documentation that no longer exists, clear the index and re-ingest.

Coupling

The melody expression is shared

to_pattern and build_prompt both call melody_expression, so the literal pattern and the one the agent must keep cannot disagree.

Coupling

One bar per cycle

STEPS_PER_BEAT, BEATS_PER_CYCLE and cpm = bpm / 4 describe one grid. Change one and setcpm stops matching the note lengths.

Coupling

Only prebaked sounds exist

The page loads dirt-samples and the built-in synths. DEFAULT_SOUND, AVAILABLE_SOUNDS and the validator's gm_ warning all encode that.

Coupling

Two Strudel versions

The page plays with @strudel/web 1.3.0; the sandbox validates with @strudel/core 1.2.6, the newest core published. A function present in only one will be judged by the other.

Runtime

The dependency stub is load-bearing

Delete sandbox/stubs and @strudel/core stops importing at all.

Runtime

Launch path matters

server.py and core.py import siblings through app/ on sys.path. Moving files breaks the imports.

Runtime

config.js is generated

sync-www.mjs injects it into the copy. If the source page referenced it, the browser version would 404 on every load.

Licensing

AGPL code on a server

The sandbox runs Strudel inside a networked service, which is the case the AGPL's network clause addresses. Worth legal review before any deployment.
